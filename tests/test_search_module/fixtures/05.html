API REFERENCE / AUTHENTICATION

Authentication

The Acme API uses bearer tokens to authenticate requests. Every request to a protected endpoint must include a valid access token in the Authorization header.

Creating an API key

API keys can be created from the developer dashboard. Give each key a descriptive name so that it can be identified later. 

Authorization: Bearer YOUR_API_KEY

Making an authenticated request

The following example requests information about the current account: 

curl https://api.example.test/v1/account \
  -H "Authorization: Bearer YOUR_API_KEY"

Response

{
  "id": "acct_12345",
  "name": "Example Account",
  "active": true
}

Security recommendations

  • Never commit API keys to source control.
  • Store credentials in environment variables or a secret manager.
  • Use separate keys for development and production.
  • Rotate keys when they may have been exposed.

Errors

An invalid or missing token produces a 401 Unauthorized response. Expired tokens should be replaced before retrying the request.
